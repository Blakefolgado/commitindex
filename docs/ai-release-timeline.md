## Display and evidence rules

- Store the availability value with each event so previews and general-availability launches remain distinguishable without hiding either.
- Plot the publisher's calendar date as UTC; most first-party posts do not provide a trustworthy launch timestamp.
- Stack same-day events instead of moving a marker to a false date, and use provider/category filters rather than dropping dense clusters.
- Do not infer causation from proximity: annotations expose timing for interpretation; they do not prove that a release changed contribution volume.
- Claude Fable 5 needs an interrupted-availability note because Anthropic suspended it on 2026-06-12 and [restored it on 2026-07-01](https://www.anthropic.com/news/redeploying-fable-5).
- Anthropic's current Claude 3.5 Sonnet page displays 2024-06-21; this ledger follows the publisher's displayed date despite some older citations using June 20.
- Replit's first Agent article is dated 2024-09-16 but says only that launch occurred the prior week, so the table uses the exact 2024-12-10 GA date instead of inventing an early-access day.
- Bolt.new's first-party history confirms an October 2024 launch but not the day, so no false daily marker is assigned. [Bolt](https://bolt.new/blog/security-audit-on-publish)
- The original Windsurf launch day and Llama 3.3 first-availability day were not recoverable from exact-dated first-party evidence, so the table uses later exact milestones rather than invented dates. [Windsurf](https://windsurf.com/blog/windsurf-wave-1) [Meta](https://ai.meta.com/blog/future-of-ai-built-with-llama/)
- Grok 4.20 has a dated model card but no verified public-availability post by the cutoff, so the card date is not treated as a launch. [xAI](https://data.x.ai/2026-04-07-grok-4-20-model-card.pdf)
- Keep each official URL beside the stored event because publishers can revise page dates, availability language, and product names.
